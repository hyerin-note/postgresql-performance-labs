enable_seqscan = ON:
- Execution Time: 335.291 ms
- Plan: Bitmap Index Scan + Bitmap Heap Scan

enable_seqscan = OFF:
- Execution Time: 351.014 ms
- Plan: Bitmap Index Scan + Bitmap Heap Scan

Observation:
- Execution plans are effectively identical in both cases.
- Disabling sequential scans did not force a different plan.
- Execution time slightly increased when enable_seqscan was set to OFF.
- This confirms that enable_seqscan is a diagnostic option and
  does not guarantee better performance.

Conclusion:
- For low-selectivity predicates, forcing planner behavior does not
  necessarily improve performance.
- PostgreSQL planner’s default choice is often already optimal.
